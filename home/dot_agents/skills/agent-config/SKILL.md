# Agent configuration for Claude Code, Codex, and Pi

Applies to Claude Code, Codex, and Pi. This machine's agent configuration is
managed by chezmoi. Treat the chezmoi source repo
(`~/.local/share/chezmoi`, managed source under `home/`) as authoritative; the
rendered files under `$HOME` are generated and must not be edited as the
permanent fix.

For how chezmoi works here — `apply`/`diff`/`cat`, source-name encoding,
templates and scripts, mapping/verification, safety rules — read the
repository-local `chezmoi` skill (`.agents/skills/chezmoi/`), which is
authoritative for this repo's mechanics. This skill is about deciding *which*
agent-config target to change and how the harnesses share configuration.

## Important paths

Shared instructions for all three harnesses:

- `home/.chezmoitemplates/AGENTS.shared.md`

Per-harness rendered instructions:

- `home/dot_claude/CLAUDE.md.tmpl` → `~/.claude/CLAUDE.md`
- `home/dot_codex/AGENTS.md.tmpl` → `~/.codex/AGENTS.md`
- `home/dot_pi/agent/AGENTS.md.tmpl` → `~/.pi/agent/AGENTS.md`

Harness-specific source directories:

- Claude Code: `home/dot_claude/` → `~/.claude/`
- Codex: `home/dot_codex/` → `~/.codex/`
- Pi: `home/dot_pi/agent/` → `~/.pi/agent/`
- Shared agent skills: `home/dot_agents/skills/` → `~/.agents/skills/`

Pi's native global skills directory is linked to the shared directory by the
chezmoi script `home/.chezmoiscripts/run_after_11-link-pi-skills.sh.tmpl`:
`~/.pi/agent/skills` → `~/.agents/skills`. Claude Code and Codex use the global
Agent Skills convention `~/.agents/skills`; keep shared skills there rather than
duplicating them under harness-specific directories.

## Choosing where to make a change

1. Applies to Claude Code, Codex, and Pi → `home/.chezmoitemplates/AGENTS.shared.md`.
2. Applies to one harness → that harness's source directory (`home/dot_claude/`,
   `home/dot_codex/`, or `home/dot_pi/agent/`).
3. Skill for all three harnesses → `home/dot_agents/skills/<skill-name>/SKILL.md`.
4. Project-specific (not user-global) → the project's own AGENTS.md/CLAUDE.md or
   harness-specific project config.
5. Setting generated by a script → update the script or its source input, not
   the generated destination.

Do not put harness-specific behavior into the shared instructions. Keep shared
guidance portable; add narrowly scoped sections to the harness template only
when a tool genuinely needs different behavior.

## AGENTS.md versus skills

Use the nearest applicable `AGENTS.md` for short, durable instructions that
should shape almost every task in its scope: scope/precedence, project
invariants and non-negotiable safety rules, repository orientation, routing
rules, and a concise pointer to deeper docs. Do not use AGENTS.md as a handbook,
command catalog, or place for long workflows.

Move repeatable, topic-specific procedures, detailed CLI references,
troubleshooting, examples, and checklists into a `SKILL.md`. A skill is the
right boundary when guidance applies only to a recognizable task, needs
substantial detail, or should be discoverable and reusable across repos or
harnesses. Keep the AGENTS.md rule short enough to stay visible.

Explicitly add an AGENTS.md reference to a skill when it has a reliable task
trigger and omitting it would make the skill easy to miss. State the trigger and
exact skill name/path, e.g. "when asked to modify agent configuration, read the
`agent-config` skill first". Do this for safety-critical workflows, tool-
specific conventions, and skills that must precede interaction with an external
system. Do not reference every skill; broad lists are instruction noise.

## Skills

A shared skill must contain a valid `SKILL.md` with YAML frontmatter including a
lowercase `name` and a useful `description`, at
`home/dot_agents/skills/<skill-name>/SKILL.md`. Do not duplicate shared skills
into `home/dot_claude/skills`, `home/dot_codex/skills`, or
`home/dot_pi/agent/skills`; those are for harness-specific or native skills.
After applying, confirm visibility at `~/.agents/skills/<skill-name>/SKILL.md`
and, for Pi, via `~/.pi/agent/skills/<skill-name>/SKILL.md`.

## Safety and review

- Never commit API keys, tokens, credentials, private keys, session material,
  machine identifiers, or unexplained high-entropy values.
- Inspect `git diff --check` and `git diff` before committing; keep unrelated
  user changes intact — no broad resets or `git add -A`.
- Do not edit `~/.claude`, `~/.codex`, `~/.pi`, or `~/.agents` directly as the
  permanent fix; change the source under `home/`, then apply (see the `chezmoi`
  skill for apply commands).
- Restart the affected harness after changing instructions, extensions,
  plugins, or settings loaded only at startup.
- If a full apply prompts for confirmation or reports an unrelated conflict,
  stop and diagnose rather than bypassing it blindly.
