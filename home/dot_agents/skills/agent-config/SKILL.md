# Agent configuration for Claude Code, Codex, and Pi

This skill applies to configuration for Claude Code, Codex, and Pi. This
machine's agent configuration is managed by chezmoi. Treat the repository source
state as authoritative; do not edit generated files in the home directory unless
you are explicitly diagnosing a rendered result.

## Important paths

Chezmoi source repository:

- `~/.local/share/chezmoi/`
- In this checkout, the source root is the current repository.

Global instructions shared by all three harnesses:

- `home/.chezmoitemplates/AGENTS.shared.md`
- `home/dot_claude/CLAUDE.md.tmpl` renders `~/.claude/CLAUDE.md`
- `home/dot_codex/AGENTS.md.tmpl` renders `~/.codex/AGENTS.md`
- `home/dot_pi/agent/AGENTS.md.tmpl` renders `~/.pi/agent/AGENTS.md`

Harness-specific source directories:

- Claude Code: `home/dot_claude/` → `~/.claude/`
- Codex: `home/dot_codex/` → `~/.codex/`
- Pi: `home/dot_pi/agent/` → `~/.pi/agent/`
- Shared agent skills: `home/dot_agents/skills/` → `~/.agents/skills/`

Pi's native global skills directory is linked to the shared directory by the
chezmoi script `home/.chezmoiscripts/run_after_11-link-pi-skills.sh.tmpl`:

- `~/.pi/agent/skills` → `~/.agents/skills`

Claude Code and Codex use the global Agent Skills directory convention,
`~/.agents/skills`. Keep shared skills there rather than duplicating them under
harness-specific directories.

## Choosing where to make a change

1. If the rule applies to Claude Code, Codex, and Pi, edit
   `home/.chezmoitemplates/AGENTS.shared.md`.
2. If the rule applies to one harness, edit that harness's source directory.
3. If the skill should be available to all three harnesses, create or update
   `home/dot_agents/skills/<skill-name>/SKILL.md`.
4. If the change is project-specific rather than user-global, edit the project's
   own `AGENTS.md`, `CLAUDE.md`, or harness-specific project configuration
   instead.
5. If a setting is generated by a script, update the script or its source
   input—not the generated destination.

Do not put harness-specific behavior into the shared instructions. Keep shared
guidance portable and add narrowly scoped sections to the harness template when
a tool genuinely needs different behavior.

## AGENTS.md versus skills

Use the nearest applicable `AGENTS.md` for short, durable instructions that
should shape almost every task in its scope. Good AGENTS.md content includes:

- Scope and precedence: what the instructions govern and which narrower files
  override them.
- Project invariants and non-negotiable safety rules, such as supported
  commands, branch policy, secret handling, or deployment constraints.
- Repository orientation: important directories, source-of-truth files,
  generated-file boundaries, and required verification commands.
- Routing rules: when to read a particular skill, use a particular tool, or ask
  for confirmation.
- A concise pointer to deeper documentation, rather than the full procedure
  itself.

Do not use AGENTS.md as a handbook, command catalog, or place for long
workflows. Move repeatable, topic-specific procedures, detailed CLI references,
troubleshooting, examples, and checklists into a `SKILL.md`. A skill is the
right boundary when the guidance is only relevant to a recognizable task,
requires substantial detail, or should be discoverable and reusable across
repositories or harnesses. Keep the AGENTS.md rule short enough to remain
visible and broadly applicable.

Choose the AGENTS.md scope deliberately:

- A repository-root `AGENTS.md` governs work in that repository and its
  descendants. Put repository-specific policy there; do not add machine-global
  guidance to it.
- A directory-level `AGENTS.md` governs only that directory subtree. Use it for
  a component, package, or nested workflow with narrower conventions.
- The chezmoi source repository's `home/.chezmoitemplates/AGENTS.shared.md` is
  the source for machine-global guidance shared by Claude Code, Codex, and Pi.
  Edit it for rules that should render into all three harnesses.
- Harness-specific files (`home/dot_claude/CLAUDE.md.tmpl`,
  `home/dot_codex/AGENTS.md.tmpl`, and `home/dot_pi/agent/AGENTS.md.tmpl`) are
  for behavior that only one harness understands or needs.

Explicitly add an AGENTS.md reference to a skill when the skill has a reliable
task trigger and omitting it would make the skill easy to miss. The reference
should state the trigger and exact skill name/path, for example:
`When asked to modify agent configuration, read the shared \`agent-config\`
skill first.` Do this for safety-critical workflows, tool-specific conventions,
and skills that must be read before any interaction with an external system. Do
not add references for every skill: broad lists create instruction noise; rely
on normal skill discovery for incidental or self-explanatory skills.

## Safe workflow

From the chezmoi source repository:

```bash
# Inspect source and current state
chezmoi source-path ~/.claude/CLAUDE.md
chezmoi source-path ~/.codex/AGENTS.md
chezmoi source-path ~/.pi/agent/AGENTS.md
chezmoi diff

# Preview a rendered file or template
chezmoi cat ~/.claude/CLAUDE.md
chezmoi cat ~/.codex/AGENTS.md
chezmoi cat ~/.pi/agent/AGENTS.md

# Apply one target when possible
chezmoi apply ~/.claude/CLAUDE.md
chezmoi apply ~/.codex/AGENTS.md
chezmoi apply ~/.pi/agent/AGENTS.md

# Apply changes involving scripts, links, or several related files
chezmoi apply
```

Use `chezmoi apply -n` for a dry run. After applying, verify both the rendered
destination and the source mapping:

```bash
chezmoi source-path ~/.pi/agent/AGENTS.md
chezmoi managed ~/.agents/skills
ls -ld ~/.pi/agent/skills
```

A targeted apply may not run unrelated `run_after_` scripts. Use a full
`chezmoi apply` when changing scripts, symlinks, skill installation, or any
generated configuration.

If chezmoi reports inconsistent state because both a plain file and `.tmpl`
source exist, remove the obsolete plain source file from the repository after
confirming the template renders the intended content, then apply the target
again. Do not keep both forms.

## Templates and scripts

Chezmoi source names encode destination paths: `dot_` becomes `.`, and `.tmpl`
means the file is rendered as a Go template. Use `chezmoi execute-template` or
`chezmoi cat` to inspect template output before applying it.

Scripts under `home/.chezmoiscripts/` may install dependencies, synchronize
repositories, create directories, or create links. Read a script before running
it manually. Preserve idempotence, avoid destructive operations, and make
missing optional dependencies non-fatal when appropriate.

When a script needs to create a link, do not overwrite an existing non-link
path. Report the conflict and leave the user's data untouched. When changing a
managed link or script, run the relevant apply and verify the final target with
`ls -ld` and `readlink`.

## Skills

A shared skill must contain a valid `SKILL.md` with YAML frontmatter including
lowercase `name` and a useful `description`. Put it at:

```text
home/dot_agents/skills/<skill-name>/SKILL.md
```

Do not duplicate shared skills into `home/dot_claude/skills`,
`home/dot_codex/skills`, or `home/dot_pi/agent/skills`. Those directories are
for harness-specific skills or native system skills. After applying, confirm the
skill is visible at `~/.agents/skills/<skill-name>/SKILL.md` and, for Pi,
through `~/.pi/agent/skills/<skill-name>/SKILL.md`.

## Safety and review

- Never commit API keys, tokens, credentials, private keys, session material,
  machine identifiers, or unexplained high-entropy values.
- Inspect `git diff --check` and `git diff` before committing.
- Keep unrelated user changes intact; do not use broad resets or `git add -A`.
- Do not edit `~/.claude`, `~/.codex`, `~/.pi`, or `~/.agents` directly as the
  permanent fix. Make the corresponding source change, then apply it.
- Restart the affected harness after changing instructions, extensions, plugins,
  or settings that are loaded only at startup.
- If a full apply prompts for confirmation or reports an unrelated conflict,
  stop and diagnose that conflict rather than bypassing it blindly.
